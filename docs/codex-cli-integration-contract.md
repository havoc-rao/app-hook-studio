# App Hook Studio → CoLink：Codex CLI

App Hook Studio owns the producer and CLI launch integration; CoLink owns approval UI, actions, history and reminders. The native CLI executable is unchanged. Do not restore the earlier synchronous PermissionRequest hook: it suppresses the native prompt while waiting.

Producer: `src/apps/codex-cli/{cli,cli-proxy,native-channel,identity}.cjs`; installer/registry: `service.ts`, `rule.ts`, `registry.ts`. Runtime is deployed under App Hook Studio application support, not CoLink. CLI registration is separate from UTF-8 application-resource patch adapters.

Discovery and transport remain compatible with CoLink: current-user private `/tmp/colink-codex-<uid>/*.sock.json`, protocol 1, one newline JSON request/response per connection, `list` / `respond`. Pending requests include supported_actions allow/reject, original command, registration snapshot, approval_channel. Request routing is private producer connection + native RPC ID; display identities never choose a response target. Completion, cancellation and disconnect clear pending entries. Native and CoLink responses share first-response arbitration.

Identity schema 1: machine source colink.machine-id / scope colink-installation; persistent UUID is kept at `~/Library/Application Support/CoLink/machine-id.json` for cross-version continuity. This is an installation identity, not hardware identity. Display hostname is not a key. Workspace uses Thread.projectId, otherwise a hash of native Thread.cwd, with explicit source and codex-thread scope; command cwd never fills missing thread metadata. Request session_id maps to Thread.sessionId, agent.id is Thread.id, parent agent is parentThreadId. `codex_context` retains native thread/session/turn/project IDs. Root thread name provides session title; preview/command is not a title. Unknown fields are null with diagnostics. Snapshot identity is not rewritten after a later rename.

Only local shell requests with complete commands are mirrored. Network, file and other approvals remain native. Proxy loss currently ends its per-connection app-server; no daemon/reconnect guarantee is made. Official CLI 0.166.0 was tested via real terminal + CoLink adapter. GUI clicking was not separately automated. Producer native-first/Raycast-first/duplicate/resolved tests use a fake owner with a real Socket and do not replace real lifecycle verification.

CoLink must accept Codex identity sources and preserve platform.source=local-codex-cli-proxy. Installed producers need a fresh terminal after update. Existing unknown historical identities are not retroactively fabricated or regrouped.

Session display extension: `list` responses may include a separate `sessions` array of `{session_id,identity,platform}` native metadata snapshots, even when no approvals are pending. `identity.session.created_at` and `updated_at` use Unix milliseconds converted from native Thread seconds. Native thread/name/updated updates this display stream; approval snapshots remain immutable. CoLink caches the latest displays separately and overlays them only on existing session rows, so metadata alone does not recreate deleted history groups. Old producers without sessions remain compatible. Metadata extraction stores only whitelisted Thread identity/name/time fields, never preview or turns.
